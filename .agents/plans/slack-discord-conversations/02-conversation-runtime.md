# WP2 — shared conversation service and agent bridge

Prerequisites: WP0 combined dependency/SDK verification and WP1 state/config. The actual upstream admission contract below is published. All host files/symbols below are **new/proposed**, inserted under WP1's new package parents: `internal/conversation/{service,routing,worker,controls,recovery}.go`, `internal/agentbridge/{runtime,resolver,projection}.go`, `internal/render/{text,chunks,delivery}.go`, and corresponding `_test.go` files. Interface names here are conceptual local contracts, not existing eino-agent APIs.

## Boundaries and routing

Proposed normalized Inbound contains platform/installation, channel, thread root, source message ID, actor, content and event kind. Adapter validates identity and mentions and checks configured allowlists before giving it to the service. Proposed Delivery adapter accepts explicit immutable destination and create/edit operation and returns remote ID plus classified definite/ambiguous failure. Agent bridge offers submit, receipt lookup, watch, interrupt and recovery through actual WP0 APIs. No Slack/Discord SDK type crosses these boundaries.

Canonical route tuples use a versioned length-delimited encoding, not slash concatenation. Slack DM = team + DM channel + actor; Slack shared = team + channel + thread root. Discord DM = bot installation + DM channel + actor; Discord shared = bot installation + guild + thread channel. Root-to-created-thread mapping is durable. Distinct platforms, installations, channels, threads and DMs never share a session. All authorized participants in a shared thread intentionally share history, even if one writes later. Their text is labelled with a stable host-local participant label in normalized input; keep labels consistent without treating display names as authority. Only bot-addressed text enters the model; no fetching channel history or message URLs.

One route has a current generation. `!new` while idle with no queued prompts or unresolved deliveries atomically rotates to fresh runtime/provider session IDs, retains old transcript, and drops no accepted prompt silently. Reject new while running, queued, or with pending/failed/ambiguous deliveries with “Finish or resolve pending work before starting a new conversation.” Only an acknowledged final-content revision counts as resolved; associating a recovered preview ID does not. Rotation and the unresolved-work check share the route transaction so completion/routing races cannot strand output. Only the thread creator may reset a shared conversation. `!stop` interrupts active execution and marks queued prompts canceled for that route; shared-thread authorization is restricted to active initiator or thread creator. At stop acceptance, atomically persist the target run ID (or admitting inbox key), highest currently accepted prompt sequence, and generation. Mark queued prompts up to that cutoff canceled in the same host transaction, retaining interruption-pending state for the target. Recover pending controls before dispatching any queued work on that route. Pause that route's admission across this decision; if a turn is already admitting, quiesce its original admission attempt, resolve its keyed receipt before applying interruption and never target a later run. If no receipt exists after that attempt has definitively stopped, mark that input canceled without starting it; an ambiguous outcome remains pending until authoritative lookup resolves it. Stop recovery looks up only the frozen target, interrupts if owned/active or lets lease recovery settle it; an already terminal target is success. Mark control complete after both queue cancellation and target settlement; replay is idempotent. Prompts accepted after the cutoff survive stop replay. Other actors get a fixed denied notice. `!help` lists addressing, limits and controls. Commands require the same routing and allowlist checks and are not submitted to the model. Deduplicate controls durably; repeat stop is harmless. DMs permit owner controls. Literal text not exactly matching a reserved command remains conversation input.

## Durable ingress and admission

Use `github.com/mattsp1290/eino-agent@v0.3.4-0.20260910151824-b77c7e64e09d`. Set `runtime.Request.AdmissionKey` to a persisted opaque ASCII event key (for example `evt-` plus a SHA-256 hex digest of the canonical platform event tuple), within session.ValidateAdmissionKey's 1–256-byte alphabet. Request.SessionID scopes the key.

Consume `runtime.AdmissionResult` from Start. On AdmissionNew, save Receipt and retain its nonnil Handle for the sole Done/Interrupt owner. On AdmissionExisting, save the same Receipt but expect nil Handle; observe through store/watch and do not call Resume merely because a duplicate was received. Startup lease recovery remains a separate host decision. Unkeyed Start also returns AdmissionResult; no bridge call may assume the old direct-Handle return.

Use root `session.Store.LookupAdmission(ctx, sessionID, key)` for recovery before runtime construction, or configured `StreamingOrchestrator.LookupAdmission` otherwise. Both return session.AdmissionRecord, containing immutable Receipt, fingerprint version/digest and point-in-time RunStatus. Lookup must be outside a store transaction. ErrNotFound from a successful authoritative read permits retry of the same frozen keyed request after quiescing its original attempt; ErrAdmissionUnknown, ErrAdmissionStore, cancellation and other failures remain unresolved. ErrAdmissionConflict is terminal and content-free; ErrAdmissionInvalid rejects malformed input. Never manufacture execution authority from a receipt.

Freeze v1 fingerprint inputs in the inbox: Message.Content; Config.Agent name/system prompt/mode/model/options; Config.Model; Config.Tools enabled/disabled/permissions (preserve slice order); Config.Metadata and Request.Metadata. Keep nil/empty collections semantically equivalent and never alter included fields on retry. The library hashes its fixed JSON payload with the `eino-agent-admission-v1` plus NUL prefix; do not implement a second encoder. It excludes Config.Observability, resolved auth and runtime dependencies. Its input ceilings are 256 KiB message and 1 MiB encoded payload; host limits below are stricter. No workspace_root is necessary for this tool-free service; if supplied, it must be absolute and cleaned.

The published SQLite/PostgreSQL admission_receipts schema is transactional and immutable through terminal/reclaimed runs. Old development baselines are rejected without mutation. Start the new host with explicitly fresh databases; never auto-recreate existing files or combine an old database with this pin. See the canonical response for source/CI evidence and schema consequences.

Within each route generation, process accepted prompts by host commit sequence, not timestamp sorting. Incoming late events enter in receive order. Filter own/bot/webhook events, edits/deletes, blanks and unsupported attachment-only messages before admission. On mixed text + files use only text and a fixed notice that files are not read. Overflow or oversize is a terminal rejected inbox record with one safe user notice and no provider request; duplicate rejection does not make another inference. Reserve a small bounded control lane.

State machine: received → queued → admitting → admitted(receipt/run) → terminal → delivery pending → delivered or ambiguous/failed delivery. Rejected/canceled states never reach the model. The receipt is the authority at the admitting boundary. Freeze normalized input, selected model/prompt version and non-secret configuration before first Start; reuse identical payload and admission key from the inbox after any crash. Include only stable session metadata in Request.Metadata; do not put a changing message ID there, because agent admission compares it for session identity.

After a crash in admitting, query keyed receipt first. If present, associate original run and observe/recover it; do not Start a new run. If authoritative absence, retry the original keyed request. Duplicate admitted/completed events reuse the original receipt and delivery records. Never regenerate an answer to repair a send. Stop on a fingerprint conflict with a safe operator diagnostic. Do not use model.Request.IdempotencyKey as user admission idempotency; it addresses a different boundary.

Runtime owns all user/assistant persistence; send only current normalized message. Never dual-write messages or concatenate host replay back into Request.Message. Provider history must show one copy of each admitted input in receive order after restart.

## Tool-free provider wiring

Build one empty composition.NewRegistry(nil), no mounts or extensions, and use WithRunPlanProvider. Explicitly WithAttempts(1); no host generation retry/fallback. Configure WithStore, WithModelResolver, WithIDGenerator, unique process WithOwnerID, WithLease(5s) and WithSessionObserver. Use the published host-owned SQLite API from WP0.

Resolver accepts exactly provider `opencode-go` and model `deepseek-v4-flash`. Build opencodego.NewChatModel with ProtocolChatCompletions, explicit key, truthful UserAgent `eino-channels/<version>`, MaxTokens 4096 and default OpenCode Go base URL. A new bridge StreamProvider wrapper derives per-call `opencodeauth.WithSessionID` using a stable opaque ID for request.Identity.SessionID, then invokes model.NewEinoStreamer. Do not store a changing session fallback on a shared model. Confirm the actual auth helper signature in WP0. Never read credentials from model.Runtime metadata or serialize API keys.

Assert request.Tools is empty before invoking the model. No WithTools with nonempty tools is allowed. A provider-generated tool call fails the turn with a safe unsupported-output error; do not materialize tools or follow the call. Do not display reasoning or schema.Message.Extra. If native reasoning is necessary for plain-text Flash continuation, WP5 must expose that gap and route a narrow provider request before release; do not copy Codex private-state semantics speculatively.

Bound history before admission to 100 admitted turns and 256 KiB aggregate user/assistant display text per generation, using bounded public store reads and early exit. At that limit reject with an instruction to use !new; do not silently drop old context. Persist no extra transcript copy. Bound provider request bytes in the bridge to 1 MiB and fail safely if exceeded. Cap accepted streamed answer text at 32 KiB UTF-8; cancel and settle interrupted with a limit notice if exceeded. Output token cap 4096 is additional, not a byte guarantee. Tests must establish that observation snapshot limits can contain the maximum supported generation; use 200 messages, 400 parts, max text 320 KiB and max encoded snapshot 4 MiB, max tools 1, rather than copying TUI's arbitrary window size. Any unforeseen observation overflow falls back to a safe unavailable state, not truncated final text.

## Projection, delivery and lifecycle

Use watch.NewService and WithSessionObserver, subscribe before admission, and match session/run/message/attempt identities. Durable replaces state; live replaces its overlay. Never append live snapshots repeatedly. On finalization purge overlay and render committed text. Empty placeholder produces a “Thinking…” status only, never an empty completed assistant message. Closing watch cannot cancel inference. On ErrResyncRequired create a new watch; bounded retries (three with backoff), then continue awaiting run completion and use bounded committed reads for final text. Keep one authoritative Done consumer, fan terminal state to worker/delivery internally.

Assign each accepted prompt a durable per-route delivery sequence from the inbox FIFO sequence, and order its chunks by index. A successor preview/final cannot overtake an unresolved predecessor. Failed or ambiguous predecessor delivery pauses that route's delivery lane until operator resolution; other routes and model workers remain independent. Priority control notices can report this blockage without implying that a later answer was delivered. Persist the ordering cursor and recover it before draining output. Test A's stalled final, B's completed answer, rejected !new and restart, then resolve A and prove A/B delivery order.

Delivery pipeline keeps latest preview per active run, coalesces at most once per 1.2s per destination and honors stricter platform rate feedback. Preview is explicitly transient; after a restart, unavailable text becomes an interrupted/failure notice instead of a false final answer. Final chunking runs only from committed text. Use 1800 UTF-16 units for Discord and 3500 Unicode characters for Slack including labels/escaping. Split on paragraphs/newlines when possible, otherwise Unicode-safe boundaries. Balance code fences or escape malformed fences; no bytes lost or duplicated. Render platform-specific mention suppression and disable link unfurls. No rich block output required.

Create one status/preview message; persist its remote ID and edit it for first final chunk, append additional final chunks sequentially, each with durable unique index. Keep created earlier chunks fixed during streaming (v1 previews only the first chunk with a continuation notice). Final text, partial interrupted text and safe status are distinct. Permanent delivery failure or permission loss does not change the committed run's model status. Recheck allowed destination and generation before dispatch; removed allowlist access prevents sending stored output. An old run's response never targets a new generation.

Before every create, persist an intent. A timeout/disconnect after create is ambiguous: do not retry blindly. Discord nonce reconciliation and Slack operator association are adapter-specific. Recovering a create only establishes the remote message ID. Persist desired final revision separately from acknowledged content revision; association always leaves the current committed final edit pending. Only a successful final edit/create acknowledgement advances the delivery cursor and clears its payload. Known remote-ID edits can be retried with latest state; 429 waits are bounded and cancelable. Store retry state on disk, cap automated attempts at five over ten minutes, then mark failed/ambiguous for operator resolution. `docs/operations.md` specifies recovery using stored run/delivery references with explicit operator resend choice; no new model call. No exactly-once external-send claim.

Disconnecting either gateway never cancels an admitted model run. On service restart scan bounded batches of pending inbox/delivery records, lookup receipts and active runs. Wait for a live lease before Resume; no-tools Resume settles the abandoned turn interrupted without rerunning provider. Keep admitted user and any committed partial assistant content; explain interruption, then permit new input. Startup must not need a fresh platform event to recover old runs. A genuinely new queued prompt may run after recovery under its original key.

Shutdown: stop ingress/admission, preserve queued rows, interrupt owned handles, await terminal settlement until 10s deadline, stop delivery, close subscriptions/watch, close SDKs and pools, release lock. Timeout exits nonzero with fixed diagnostic and leaves recovery records intact. Ensure status notifications during shutdown cannot outlive closed SDKs. Distinct conversations may execute in parallel up to four; a blocked destination cannot consume every model worker.

Acceptance additionally covers terminal run → pending/ambiguous delivery → rejected !new → operator resolution → successful !new, including restart; crash/replay at each stop side effect must leave later-sequence input intact.

Acceptance: real agent/SQLite + real provider adapter/fake HTTP tests prove two turns + reopen, empty tool schemas, distinct parallel session headers, zero duplicate inference across crash boundaries, bounded output/history, stop/new authorization, queue ordering/overflow, watches that overflow/detach, interrupted no-tools recovery, provider auth/quota/timeout/truncated SSE and delivery 429/ambiguous create. Run `go test ./internal/conversation ./internal/agentbridge ./internal/render` and race equivalents. Add sentinel secret strings to failure fixtures and assert absent from chat diagnostics/logs.
