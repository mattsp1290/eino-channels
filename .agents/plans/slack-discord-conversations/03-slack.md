# WP3 — Slack Socket Mode

Prerequisites: WP2 stable interfaces; can proceed alongside WP4. New/proposed files under WP1 parent `internal/slack/`: `adapter.go`, `events.go`, `delivery.go`, corresponding tests. New `docs/slack-setup.md` under WP1 docs parent and `slack-manifest.json` under existing repository root.

Use slack-go/slack socketmode with bot token for Web API and app-level token for Socket Mode. Installation is operator-managed, one configured team. Proposed manifest enables Socket Mode, app-level connections:write, bot scopes app_mentions:read, chat:write, im:history, and event subscriptions app_mention and message.im. Enable App Home messages. Invite bot to each configured public/private channel; channel history read is unnecessary because follow-ups require explicit mentions and the host stores accepted history. Include no chat:write.public, user token or OAuth/distribution flow. Validate team/bot identity at startup through auth.test and reject mismatch; never print returned identities/tokens.

Authorize team, configured user ID, and shared channel before model work. DM plain text is accepted; root app_mention begins a thread keyed by its timestamp. A mention already in a thread uses thread_ts. Strip only the actual leading bot mention, never arbitrary user mentions within content. Reply to channel + root thread_ts with reply_broadcast false. Require a fresh @bot mention on shared-thread follow-ups and controls. DM threaded replies use the same DM conversation; do not fork or import unrelated message history. Dedup canonical team/channel/message ts across app_mention and message event representations, not envelope_id. Ack every transport envelope independently, even when its logical message is a duplicate.

Use the preauthenticated websocket envelope for ingress. Filter bot_id, own user, subtypes including edits/deletes, hidden and message_changed wrappers. Reject Slack Connect/external shared-channel events in v1 until identity policy is explicitly extended; do not accept a sender merely because the channel ID matches. Match configured local team and actor allowlist. Unsupported event kinds are acknowledged and ignored.

Durably store accepted/rejected disposition within a target one second before ack (Slack deadline is three seconds); never wait for provider or Web API. If database write cannot finish before deadline, do not ack runnable input; Slack retries may redeliver. Let SDK ack retry independent of worker execution. Acknowledgement after persistence means process death cannot lose an accepted prompt. When overwhelmed, persist a rejected disposition and schedule one bounded busy notice; do not spawn unbounded ack workers.

Use chat.postMessage/chat.update with text only, parse none, link_names disabled, unfurl_links and unfurl_media false. Escape ampersand/angle brackets and neutralize Slack mention syntax in model output. Split at WP2's 3500-character budget after escaping. Maintain one editable preview and ordered final chunks; rate-limit by destination at 1.2s minimum and respect Retry-After. Disable verbose SDK logging.

A create with definite error can retry under WP2 policy. A create with unknown outcome becomes ambiguous_create. v1 has no history scope for automatic Slack reconciliation: expose safe local delivery status and document manual inspection of the destination followed by explicit associate-message or resend resolution via a proposed `eino-channels delivery resolve` command in WP5. Do not claim client_msg_id guarantees exactly-once sends. Auth revocation halts this adapter and records health; Discord can continue. Connection refresh/reconnect uses SDK lifecycle; accepted work continues and deliverable output waits durably.

Tests: real Slack SDK pointed at fake Web API plus synthetic Socket envelopes, ack captured before provider is released, same message across two envelope IDs, app_mention/message collision, bots/subtypes, DM/thread destination, external-team/shared-channel rejection, allowlists, escaped mentions, Unicode/fences/long output, rate headers, edit failure, ambiguous create and reconnect. Acceptance: allowed DM and shared thread each complete two turns, reply remains in correct thread, unauthorized events cause zero provider requests, reconnect/restart never duplicates admission.

Sources checked during planning: [Socket Mode](https://docs.slack.dev/apis/events-api/using-socket-mode/), [Events API](https://docs.slack.dev/apis/events-api/), [chat.postMessage](https://docs.slack.dev/reference/methods/chat.postMessage/). Recheck setup fields and SDK methods in WP0; current protocol constraints are not frozen platform guarantees.
