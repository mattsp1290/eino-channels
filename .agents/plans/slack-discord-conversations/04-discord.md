# WP4 — Discord Gateway

Prerequisites: WP2 stable interfaces; can proceed alongside WP3. New/proposed files under WP1 parent `internal/discord/`: `adapter.go`, `events.go`, `threads.go`, `delivery.go`, corresponding tests. New `docs/discord-setup.md` under WP1 docs parent.

Use DiscordGo with bot token, Gateway intents Guilds, GuildMessages and DirectMessages. Accept plain DMs and explicit bot mentions in configured guild text channels or their public threads. Mentioned messages and DMs have message-content exceptions; v1 does not require privileged MessageContent or ingest unmentioned thread traffic. Gateway readiness must establish own bot identity before processing input. No slash-command registration or public HTTP interaction route is required. Never use a user token.

Document bot installation and effective View Channel, Send Messages, Send Messages in Threads, Read Message History and Create Public Threads permissions. Private threads, forums, group DMs, voice and announcement channels are out of scope. Validate configured parent-channel/guild and actor allowlist on every event; determine a thread's parent from trusted SDK/API channel metadata with a bounded cache, fail closed if unresolved. Do not authorize a thread by its name. Ignore other bots, webhooks, own messages, edits and deletes.

DM key uses bot/DM-channel/actor. In an allowed ordinary text channel, the first explicit mention creates a public thread from the source message with a fixed content-free name, binds its thread ID durably, and routes model replies inside it. Thread creation precedes model admission. Public-thread source-message relationship provides reconciliation: on ambiguous creation, fetch the source/channel-thread metadata to identify the already-created thread before retrying. If unresolved, mark ingress routing blocked and show a fixed failure where possible; never create multiple threads or run a model before destination is known. A mention in an existing allowed public thread uses that thread directly. Follow-ups and !controls in threads require @bot each time; DMs do not. Unarchive an existing writable thread only if API/permissions permit; otherwise produce a fixed destination-unavailable result without guessing a new route.

Dedup key is bot installation/channel/message snowflake; Gateway sequence number is not durable identity. Gateway has no application event ack; persist quickly, reconnect/resume through SDK and rely on keyed admission to absorb replay. A successful resume can replay events but a fresh non-resumable connection does not establish offline backlog delivery. Document missed-during-downtime limitation and ask user to resend visibly unanswered prompts; automatic history backfill is out of scope.

Send reply messages with AllowedMentions empty parse/users/roles and replied_user false on every create/edit; disable everyone/role/user notifications even if the model outputs raw syntax. Suppress embeds where supported. Apply 1800 UTF-16-unit chunk budget including labels/fences, below the 2000-character API cap. Preserve Unicode and committed text. Use a per-route/global-aware limiter with server retry_after/bucket signals. Typing indicators may supplement the preview but are not proof of admission or completion.

Persist a stable <=25-character nonce per delivery operation and use enforce_nonce if supported by selected SDK/API. Prove actual wire fields; this provides only a recent dedup window. For ambiguous sends, bounded history lookup of the destination (up to 100 recent messages once per retry cycle) may reconcile own messages by nonce when available. Content equality alone is insufficient. If no unique evidence, retain ambiguous_create and use WP5 operator resolution; never claim nonce covers indefinite restart. Known remote IDs permit idempotent edit retries. Deleted output/archived thread/403 produce visible failed delivery state without new inference.

Tests: real DiscordGo HTTP client against fake API, fixture MessageCreate and thread metadata, IDs > JavaScript safe integer kept as strings, concurrent root replay creating one thread, ambiguous thread create recovery, mentions versus plain guild text, DM author filtering, parent allowlists, lost permissions, AllowedMentions on create/edit, nonce wire payload, Unicode/long answers, route/global 429, resume duplicate and non-resumable disconnect behavior. Acceptance: live DM and guild public-thread two-turn exchanges, !stop/!new policy, restart continuation, no unintended mentions and correct output chunk order.

Sources: [Gateway intents](https://docs.discord.com/developers/events/gateway#message-content-intent), [Message resource](https://docs.discord.com/developers/resources/message), [Rate limits](https://docs.discord.com/developers/topics/rate-limits). Recheck API/SDK behavior at WP0 and installation during WP5.
